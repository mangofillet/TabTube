# TabTube — Flatpak / Flathub

These files package TabTube as a Flatpak and are the basis of a Flathub submission
(which is how it appears in GNOME Software, KDE Discover, and **Linux Mint's Software
Manager**).

## Approach: repackage the prebuilt release (mirrors upstream FreeTube)

FreeTube's own accepted Flathub manifest
([`flathub/io.freetubeapp.FreeTube`](https://github.com/flathub/io.freetubeapp.FreeTube))
does **not** build from source — it repackages FreeTube's prebuilt Linux release
artifact onto the Electron base app. TabTube (an AGPL Electron fork of the same app)
mirrors that proven approach: the manifest downloads the released
`TabTube-<version>.AppImage`, extracts it, and bundles it with a zypak launch wrapper.

Files:
- `io.github.mangofillet.TabTube.yml` — Flatpak manifest (repackages the released AppImage).
- `run.sh` — launch wrapper (zypak sandbox + writable `TMPDIR`).
- `io.github.mangofillet.TabTube.metainfo.xml` — AppStream metadata (store listing). The
  unofficial-fork disclaimer is in the **first `<p>`** of `<description>` (Flathub requires this).
- `io.github.mangofillet.TabTube.desktop` — desktop entry.
- `icon-512.png` — app icon.

> If a Flathub reviewer asks for a source build, switch the `tabtube` module to build
> from pnpm source with offline npm sources generated by
> [`flatpak-node-generator`](https://github.com/flatpak/flatpak-builder-tools).

## Keep the manifest in sync with releases

On each GitHub release, update the source `url` and `sha256` in the manifest to the new
`TabTube-<version>.AppImage`. Get the checksum with:

```bash
curl -sL https://github.com/mangofillet/TabTube/releases/download/vX.Y.Z/TabTube-X.Y.Z.AppImage | sha256sum
```

The manifest's `x-checker-data` lets Flathub's update bot propose this bump automatically
once the app is published.

## Build & install locally

Uses `org.flatpak.Builder` and the Electron base app (runtime 24.08):

```bash
# one-time tooling
flatpak install -y flathub org.flatpak.Builder \
  org.freedesktop.Platform//24.08 org.freedesktop.Sdk//24.08 \
  org.electronjs.Electron2.BaseApp//24.08

# build (run from this flathub/ directory)
flatpak run org.flatpak.Builder --force-clean --user build-dir \
  io.github.mangofillet.TabTube.yml

# lint the manifest and the built tree (must pass for Flathub)
flatpak run --command=flatpak-builder-lint org.flatpak.Builder manifest io.github.mangofillet.TabTube.yml
flatpak run --command=flatpak-builder-lint org.flatpak.Builder builddir build-dir

# install + run
flatpak run org.flatpak.Builder --force-clean --user --install build-dir \
  io.github.mangofillet.TabTube.yml
flatpak run io.github.mangofillet.TabTube
```

## Submit to Flathub

1. **Add a real screenshot.** The metainfo references
   `raw.githubusercontent.com/mangofillet/TabTube/main/flathub/screenshot-1.png` — commit that
   PNG here. Flathub requires at least one screenshot and it must be reachable post-merge.
2. Make sure the manifest `url` + `sha256` point at the latest release.
3. Fork [`flathub/flathub`](https://github.com/flathub/flathub) (uncheck "copy the `master`
   branch only"), clone `--branch=new-pr`, create a feature branch, add these files, and open a
   PR titled **"Add io.github.mangofillet.TabTube"** against the **`new-pr`** branch, following
   <https://docs.flathub.org/docs/for-app-authors/submission>.
4. Flathub maintainers review licensing, the "unofficial fork" framing, the app-id, and
   metadata. Address feedback; once merged it's published and auto-updates.
